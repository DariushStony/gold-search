## ۳. بازبینی مستقل پیش از امضا

یک بازبین که سندها را از قبل نمی‌شناخت چهار قرارداد را برای تناقض خواند. ۱۵ یافته داشت: ۱ مسدودکننده، ۹ مهم و ۵ جزئی. همه درست بودند و همه اصلاح شدند:

| شدت | یافته | اصلاح |
| --- | --- | --- |
| مسدودکننده | جزئیات کالا چیپ‌ها را نمی‌گرفت، پس با فیلتر شهر پیشنهاد اشتباهی نشان می‌داد | `POST /products/{id}` با چیپ‌ها و snapshot (API §۴.۴) |
| مهم | سؤال واحد بودجه در سرور قابل تشخیص نبود و با BR-53 نمی‌خواند | قفل در سمت کاربر؛ BR-52 «تنها سؤال مسدودکننده»؛ BR-53 فقط درباره‌ی نیت |
| مهم | ویژگی آرایه‌ای در رویدادها مجاز نبود؛ `snapshot_id` قبل از جست‌وجو نبود | API §۴.۶ و tracking plan |
| مهم | «عیار فرض‌شده» اجرت را پنهان می‌کرد، برخلاف BR-23 و BR-59 | `partial_reason` فقط برای قطعه‌ی غیرطلا |
| مهم | منبع سوم «مشکوک» (BR-84) در BR-37 نبود | BR-37 |
| مهم | AC-GP-04 ساعت دیواری را می‌آزمود، برخلاف A-01 | AC-GP-02، AC-GP-04، TC-PR-02 |
| مهم | فهرست فیلترهای BR-60 ناقص بود؛ نقش و سطح هر چیپ تعریف نشده بود | BR-54، BR-60؛ جدول نوع چیپ در API §۳ |
| مهم | چهار سناریوی تست با قانون‌ها یا متن‌ها نمی‌خواند؛ کلیک خروجی آزمون نداشت | test-cases نسخه‌ی ۰.۳ |
| مهم | نبودن قیمت طلای زمان دریافت، داده‌ی نمونه و تعارض وزن فیلد یا متن نداشتند | `no_breakdown_reason`، `sample`، `weight_conflict`؛ TX-90 تا TX-92 |
| جزئی | نوار فاکتور مبلغ هر بخش را نداشت؛ بنر آرشیو قبل از جست‌وجو داده نداشت؛ ردیف‌های کارت پس‌انداز پیوند نداشتند | `parts`؛ `GET /status`؛ `source_url` و `url` |
| جزئی | منبع «پیش‌فرض» چیپ هیچ‌وقت رخ نمی‌داد | حذف؛ BR-56، AC-QU-06 |
| جزئی | BR-122 معیار پذیرش MVP نداشت | AC-TR-03 و TC-TR-02؛ روش‌شناسی صفحه‌ی ایستا |
| جزئی | منبع‌های تطبیق در PRD §۸ هنوز در محدوده بودند | «بعد از MVP» |
| جزئی | `relax` نمی‌گفت کدام چیپ و چند نتیجه | `chip_index` و `results_if_removed` |
